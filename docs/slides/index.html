効く（efficacy）だけでは薬にならない　体内でどう振る舞うかを示す ADMET が創薬の成否を分ける

Impact

ADMET の問題は 臨床試験での脱落や開発中止 の主要な要因

In silico

だから 合成や実験の前に計算で予測　創薬の初期段階でリスクを見極める

ML

いま 機械学習を用いた ADMET 予測モデル の研究開発が活発

日本語で言えば薬物動態　効きそうな化合物でも、ここがダメだと薬にならない

  • 読み — Absorption アブソープション / Distribution ディストリビューション / Metabolism メタボリズム / Excretion エクスクリーション / Toxicity トキシシティ
  • 創薬が難しい理由そのもの　だから合成する前に計算で当てたいという需要がある
  • 化合物の機械学習では定番のテーマで、OpenADMET が狙っているのもここ

次に繋がる光っている 2 枚が PXR の関わるところ — 代謝 (M) と 毒性 (T)

Pregnane X Receptor (PXR)

体内に入った異物や薬物を感知する核内受容体 (xenobiotic sensor)　薬物代謝酵素の転写を活性化してオンにする　主に CYP3A4（市販薬の約 50% を代謝する酵素）を制御する

Why PXR in ADMET?

Activation liabilities

薬物間相互作用 (DDI)

代謝が速まり 併用薬が有効濃度を下回る

肝毒性

反応性の高い毒性代謝物が増える

化学療法抵抗性

腫瘍細胞で抗がん剤の排出が促進される

Recent example

COVID Moonshot の Mpro 阻害剤 (S)-x38 (DNDI-6510) は PXR 活性化で代謝が速まり　有効濃度を保てず 前臨床で開発中止

Structural feature

大きくて柔軟な結合部位 → 無差別に何でも結合する性質 "promiscuous"

PXR が問題になるのは、これ自体が毒だからではなく 他の薬の効き方を変えてしまうから

  • 異物センサーとして働き、活性化すると薬物代謝酵素の転写がオンになる
  • 主に CYP3A4 を制御　市販薬の約 50% を代謝する酵素なので影響範囲が広い
  • 併用薬が有効濃度を下回る (DDI)、肝毒性、抗がん剤が効かなくなる
  • 最近の例 — COVID 向けの治療薬候補 (S)-x38 はPXR 活性が高くて代謝が速まり、有効な血中濃度を保てずに前臨床で中止になった
  • 構造 — 構造ベース創薬はふつう「ポケットが無くて困る」　PXR は逆で、大きすぎてなんでも入ってしまう

Terminology — Dose-response

化合物が PXR に結合すると 下流につないだ ルシフェラーゼ が転写されて細胞が光る
この 発光量 が活性の指標になる 濃度を振って測れば用量反応曲線が引ける

pEC5050% 効果濃度（対数）
活性値を表す ターゲットが半分活性化するのに必要な濃度の −log10 pEC50 高 → 効く濃度が低い → 活性 強 単なるタンパク質と ligand の親和性 (affinity) とは異なるのがポイント 細胞への取り込み・代謝・転写の活性化まで含んだ細胞応答なので 様々な要素が関係する
Emax最大効果
濃度を上げきったときの応答の高さ pEC50 が「どの濃度で効くか」なら Emax は「どこまで上がるか」
counter assayPXR-null 対照アッセイ
PXR の影響を除いた対照測定 化合物そのものが光っていないかを確かめる primary ○ / counter × → PXR 依存 = on-target primary ○ / counter ○ → PXR 非依存 = 偽陽性
  • pEC50 — EC50 が 1 µM なら 6　数字が大きいほど低い濃度で効く＝強い
  • Emax — 「どの濃度で効き始めるか」と「どこまで上がるか」は別物　両方揃って曲線が決まる
  • counter assay — PXR の DNA 結合部位を持たない細胞系　差が 1.5 log 以上あるものを on-target とみなす

聞かれたら学習データの pEC50 は平均 4.32、最大 7.55。6 以上は 4,140 件中 67 件しかない

Terminology — Primary screen

single-conc単一濃度スクリーニング
一次スクリーニングとして 1 濃度のみで測定する 用量反応曲線を引かないので EC50 は出せない 代わりに低コストで 桁違いに多くの化合物をカバーできる
log2fclog2 fold-change
single-conc の応答を対照との比で表し log2 をとった値log2fc = log2( 化合物ありの発光量 / 対照の発光量 )

要するに pEC50 そのものにはなれないが、活性のシグナルは持っていて、しかも数が多い

  • 単一濃度なので曲線が引けず EC50 は出せない　「効いたかどうか」に近い情報
  • log2fc は対照との比の log2　0 なら対照と同じ、1 なら 2 倍
  • 高濃度側は飽和して強い化合物どうしの差が潰れる　だから 2 濃度の性格が違う
  • log2fc は test に存在しない　だから後半は実測ではなく予測値を使う話になる

聞かれたら2 濃度の差は実データにも出ている。pEC50 との Spearman は 8.25 µM で 0.73、33 µM では 0.25 まで落ちる

Terminology — Metrics

最終評価は MAE　Leaderboard (LB) からは他の指標も得ることができる

予測が実測からどれだけ離れているか その絶対値の平均

MAE —

帯の長さがその化合物の誤差 その平均が MAE 単位は pEC50 のままなので 0.41 は「平均して 0.41 外している」

MAE を「平均値をいつも答えるモデル」の MAE で割った値

RAE —

—

1 を下回れば平均を答えるより マシということ 単位が消えるので データセットが違っても比べられる

ばらつきのうち何割を説明できたか

R² —

点が破線に乗るほど 1 に近づく 二乗なので大きく外した点ほど強く効く

値ではなく順位がどれだけ一致しているか

ρ —

d は各化合物の順位の差 最初は全て一致していて ρ = 1 順位を入れ替えると交差した線の数だけ ρ が下がる 値を全体にずらしても線は平行に動くだけなので ρ は変わらない

順位を決めるのは MAE ひとつ　残りは参考値

  • どのタブも同じ 8 化合物・同じ予測から始まる　違うのは指標が何を見ているかだけ
  • コーラルの予測をドラッグすると帯の長さと数値が動く
  • RAE の分母は「常に平均を答えるモデル」の誤差　1 未満なら平均予測よりマシ
  • ρ は順位しか見ていない　「全体を +0.8 ずらす」を押すと MAE は悪化するのに ρ は 1 のまま

触れないKendall τ もほぼ同じ話なので飛ばす。値だけ結果スライドに出る

OOFOut-Of-Fold

その化合物を 学習に使っていないモデル の予測

OOF MAE= 各 fold の MAE の平均上例の OOF MAE = 0.528

* 本来の OOF MAE は全件の予測を繋いで 1 回で計算する　今回は実用上問題なし

5 回まわすと、学習 4,140 件すべてに「その化合物を学習に使っていないモデルの予測」が 1 つ付く　これが OOF

  • 各行が 1 回の学習で、コーラルの列がその回の val　fold は 818〜832 件
  • ランダム分割だと似た化合物が train と val の両方に入り、OOF が楽観的になる　それを避けるのが目的
  • メンバー選択もキャリブレーションも全部 OOF の上でやる

聞かれたら分割は fingerprint を UMAP で低次元に写してからクラスタリングし、同じクラスタは train か val の片方にだけ入れる方式。scaffold と違って「共通骨格を持つか」ではなく「fingerprint 全体が近いか」でまとめる

Why UMAP?

ほかの分割も試した　val の中身に差はなかった

分割 どう切るか val 件数 y 分散 val→train NN coverage
random 無作為に 5 等分　比較の基準 828 0.864 0.396 100%
UMAP fingerprint → UMAP → KMeans　前スライドの手順 828 0.861 0.340 100%
scaffold 共通骨格ごと　定番だが今回は骨格がほぼ単独で効かない 828 0.862 0.388 100%
analog-only test の作り方と同じ手順で切る 170 0.676 0.414 20.5%
mixed analog analog-only を coverage 100% に直したもの 828 0.863 0.398 100%

y 分散は random とも区別がつかない　差が出るのは NN だけで、UMAP が最も遠い＝最も厳しい　analog-only は coverage 2 割で OOF が作れない

上の 2 つを、同じモデルで実際に提出OOF MAELB MAE乖離
UMAP 0.528 0.574 +0.046
analog-only 0.464 0.580 +0.116

OOF が良く見えたのは val の分布が狭かっただけ　ここは時間をかけるところではないと判断して UMAP のまま進めた

決定的に優位な分割は無かった　結果的に Morgan UMAP が一番無難だった

  • scaffold が効かないのは、Murcko 骨格 3,676 種のうち 3,532 種が 1 化合物だけだから　化合物ベースで 85.3% が単独で、実質ランダム分割になる
  • analog-only は一度は最良と結論づけたが、翌日の A/B 提出で棄却　170 件の val に過学習していただけだった
  • NN Tanimoto が低いほど val が train から遠い＝厳しい　UMAP を選んだ根拠はこれだけ
  • umap は常に 0.012〜0.025 だけ悪く出る　見積もりとしては一番正直

聞かれたら同じ特徴量 7 組で umap と scaffold を比べると順位の Spearman は 0.964。隣り合う 1 組が入れ替わるだけで、順位はほぼ変わらない

low-fidelity 一次スクリーニング　単一濃度 低コスト・大量・noisy
→ 一部だけが進む
件数の差は 500 倍以上
high-fidelity 用量反応　pXC50 高コスト・少数・これが予測したい値

この low-fidelity 側を、high-fidelity の予測にどう活かすか

比較した 6 通り数字は 51 ケース中
最良だった回数

  1. 生の LF ラベルを特徴量に足す10
  2. LF モデルが予測したラベルを足す3
  3. ハイブリッド　学習は実測　推論は予測2
  4. LF モデルのembeddingを足す10
  5. LF で事前学習して 通常どおり fine-tune0
  6. LF で事前学習し readout だけ fine-tune26

結論

生ラベルを足すだけで MAE が 10〜40% 下がり、embedding はそれをさらに最大 10% 上回る
効くのは adaptive readout があるときだけ　表現を使った 41 勝のうち 40 がそちら側

この論文の設定が、今回のデータ構造とほぼそのままだった

  • fidelity は「フィデリティ」　測定の忠実度のこと　low = 粗いが大量に測れる、high = 正確だが少ない
  • LF = 単一濃度の一次スクリーニング、HF = 用量反応で pXC50　件数差は 500 倍以上になることもある
  • 6 通り比べた勝敗が右の数字　最多は readout だけ fine-tune の 26、次が生ラベルと embedding で各 10
  • 効くのは adaptive readout があるときだけ　表現を使った 41 勝のうち 40 がそちら側

聞かれたらsum readout だと embedding も予測値も MAE がほとんど下がらず、悪化することさえある。つまり「悪化」は戦略の性質ではなく readout の性質

次に繋がるdiscussion に「embedding は random forest や SVM でも使える」とある。下流が深層でなくてよい

Strategy — TabPFN

Accurate predictions on small data with a tabular foundation model

Noah Hollmann et al.　Nature (2025)　DOI: 10.1038/s41586-024-08328-6　GitHub　使うのは実装 TabPFN v2.6

何が違うか表データのための
基盤モデル

ふつうの機械学習は、データごとにモデルを学習させる　TabPFN は学習させないGPT が文章を読んで続きを返すように、
合成表データで事前学習した Transformer が表を文脈として読んで予測を返す (In-Context Learning)

長所と短所

効くところ

  • チューニングが要らない　既定のまま強い
  • 深層学習が苦手な小さい表でも高精度

苦しいところ

  • 次元数に敏感　何列渡すのが最適かが読みにくい
  • 中身は深層学習　GPU が要る

今回の使い方

この後に出てくる 9 メンバーすべての readout　特徴量の作り方が違うだけで、最後に読むのは常にこれchallenge 中に v3 が出たが、手元では v2.6 のほうが精度が良かったのでそのまま

ほかの候補

readout は LightGBM や KAN でも試し、TabPFN に近い tabular DL model (TabM / TabICL / TabFM) も見たうえで、最良の TabPFN を採用

データごとの学習をしない　訓練データを文脈として渡して推論する

  • prior からサンプルした合成データセットで事前学習した prior-data fitted network　推論は in-context learning
  • v2 で回帰に対応した　今回は pEC50 の回帰なので v2 系が要る（使ったのは v2.6）
  • 1 万サンプルまでの表で強い　列数・行数に上限があるのが弱点で、大きな表には向かない

並びは重み順　単体の強さ順とずれるのが見どころ

  • Boltz-pocket は単体最下位 0.4860 なのに重み 0.046、GatedGCN は 0.4739 と上なのに 0.018
  • 理由はメンバー間の相関　全ペアで 0.81〜0.98、平均 0.88　tabular の 2 つは 0.98 でほぼ重複している

Members — Boltz Trunk

名前に反して この 2 つは Boltz-2 の予測構造を使っていない　Boltz trunk の embedding を TabPFN に読ませる

予測の条件

Input: PXR-human 全長 434 残基 (UniProt O75469) + 各リガンド (train + test 4,653)*

オプション: MSA: AFDB　Template: なし　Pocket 指定: あり (13 残基)　sample: 1　recycle: 3

* 前処理エラー 3 件　1 件は修正して復旧　2 件は断念 (Au 錯体 / 3D 配座を作れず)

pooling 設計

違いは pool する範囲だけ　pocket → Boltz-pocket　全体 → Boltz-allpairs

構造予測器を、構造ではなく表現として使った

  • この 2 メンバーは予測されたポーズを一切使わない　構造予測器の上に建った表現モデル
  • trunk の内訳は 1,024 次元 — s (per-token) 384+384 と z (token-pair) 128+128
  • どの残基で pool するかはほとんど効かない　効くのはペアテンソルの潰し方で、mean は良いが max だけだと 0.576 に崩壊する
  • z 単体で約 0.489 と single より強い　Boltz-2 自身の affinity module がペアを重視するのと整合する

経緯trunk を使う構想は最初からあった。co-fold に 4 日以上かけた一方でポーズ由来の特徴が振るわず、その計算を無駄にしないために作り込んだ

Members — Boltz as a Representation

どこが効いたか

効いているのは z のペア表現　128 次元だけで 0.490 と 全部入りの 0.486 に肉薄する

s は 768 次元あっても 0.507　リガンド単体の形より 残基とリガンド原子の関係が効いている　Boltz-2 自身の affinity module がペアを重視する設計とも整合する

唯一の非 log2fc

9 メンバーでここだけが log2fc を一切使わない　他メンバーとの相関も平均 0.85 と最も低い　全体は 0.88

構造だけを見て単体 0.486　他の全メンバーを駆動している log2fc の信号なしでこの水準に届く　削ると OOF は良く見えるのに public LB が悪化したので意図して残している

基盤モデルとして

構造生成と長い diffusion を飛ばせる　trunk だけなら軽く 大規模な化合物集合にも回せる

同じ考え方は PXR 以外の標的、binding / non-binding 分類、selectivity の補助表現にも広げられる　構造予測モデルをポーズを出す道具ではなく protein-aware な表現抽出器として使う方向

おまけ: pose

pose 由来は confidence までの利用にとどまった

affinity と confidence は tabular core の特徴量として入っている　pose そのものから作った特徴は gain が出ず不採用

この標的では Boltz-2 は 構造予測器 としてより 学習表現 として価値があった

重みは合計 0.081 と小さいが、外すと LB が悪化した

  • 他メンバーとの相関が平均 0.85 前後　パック全体の 0.88 より低い
  • drop や swap を試すと OOF では良く見えても public LB が悪化した　tabular 系への過集中を避ける diversity reserve
  • MoLFormer-XL を直接 fine-tune したものが 0.529　構造由来の 0.486 はそれより強い

正直に構造が唯一の勝ち筋というわけではない　答え合わせ後の test では、ゼロから学習した ChemProp も約 0.484 に届いている。PXR 1 例で一般化を主張するのは早い

聞かれたら不採用にしたポーズ由来は ProLIF の interaction fingerprint。Boltz-2 から取れる表形式シグナルは affinity/confidence スカラーとポケット集計にすでに吸収されていた

Ensemble

Caruana forward selection重みは係数ではなく 選ばれた回数

  1. 空のアンサンブルに
    OOF が一番下がる 1 つを足す    同じメンバーを何度でも足せる
  2. メンバーを絞って
    20 回やり直す    毎回ちがう顔ぶれで競わせる
  3. 採用された
    回数がそのまま重み    連続値を当てないので一極集中しない

単体の強さと重みは 一致しない　左 単体の OOF MAE　右 アンサンブルでの重み

左が単体の強さ、右が重み　順位が入れ替わる

  • GatedGCN は OOF 5 位なのに重み 8 位、Boltz-pocket は OOF 8 位なのに重み 5 位
  • 左は上下反転して「良いほど上」、右は 0 起点の実値　だから上位 4 つへの集中がそのまま見える
  • Caruana bag20 の重みは選ばれた回数という離散値なので、連続最適化より一極集中しにくい

9 メンバーはほとんど同じことを言っている　全ペアで 0.81〜0.98、平均 0.88

  • tabular の 2 つが 0.98、Boltz の 2 つが 0.97　どちらもほぼ重複
  • だから「新しいメンバーを足す」は途中から効かなくなった　これがアンサンブルの打ち止め

注意この相関は test 予測どうしのもので、重みを決めた OOF の相関ではない　OOF で計算すると 0.90〜0.99・平均 0.93 まで上がり、Boltz と他の差はほぼ消える。だから「Boltz だけ低い」とは言わない

聞かれたら高相関で落としたものの例 — ChemProp 派生、KAN readout、再 pool した Boltz trunk (既存と r ≈ 0.98)、Uni-Mol v2 (最小 r 0.899)

Calibration

順位は当たっているのに 目盛りと中心がずれていた

診断

Spearman・Kendall・R2 は上位なのに MAE と RAE だけ悪い

どの化合物が強いかの並びは合っているが pEC50 のスケールと中心がずれている状態

メンバー追加ではなく test に寄せた重みで引いた一次式で アンサンブルの出力を後から補正

重みを作る

Morgan fingerprint で train / test を判別する分類器を作り 密度比を化合物ごとの重みにする

P(test|x) / (1 − P(test|x)) を [1/3, 3] でクリップ　分類器が強すぎると少数の test 似の化合物に引っ張られるためクリップが必須

直線を引く

その重みで OOF 予測 4,140 件と正解ラベルから一次式をフィット　5-fold nested CV で検証

傾きが正なので並び順は壊れず スケールと中心だけ動く　test に似た化合物ほど この直線の決定に効く

test に当てる

同じ一次式を test 予測にそのまま適用

使ったのは test 化合物の構造だけ　正解ラベルは一切見ていない

発端は「順位系の指標は上位なのに MAE だけ相対的に悪い」という診断

  • 候補は 4 つ　採ったのは 傾きが正のアフィン　Spearman をほぼ保ったまま MAE を補正できるから
  • spline と isotonic は OOF で勝てない、または過学習気味だった
  • nested CV 上の改善は小さかったが、public LB では 0.4423 → 0.4358 と効いた　OOF 上の小さなスケール補正が Analog Set で増幅された

聞かれたら出荷版の係数は slope 1.0936 / intercept -0.3853。重みなし版の 1.0535 / -0.2457 とは別物なので混同しない

Calibration — The Gain

アンサンブルの予測は正解より幅が狭い　強い化合物を低めに 弱い化合物を高めに出す

最終アンサンブル重みで再現　unblinded test 513 件

予測の散らばりも戻る　正解 0.996 に対し 0.703 → 0.767

帯域ごとの MAE 変化

Spearman は 1 つも動かない　順位を保ったまま スケールと中心だけが直るただし効くのは主に高活性側　中域 (pEC50 3〜5) では微悪化する

補正は予測の縮こまりを広げている　散らばりが正解 0.996 に対し raw 0.703 → calibrated 0.767

  • 全体は MAE 0.4209 → 0.4077　AS1 も AS2 もほぼ同じだけ良くなる
  • Spearman は 0.8370 のまま完全に同一　単調変換なので順位は 1 つも動かない
  • 右の図は帯域別　棒が負なら改善

正直に全域で良くなるわけではない　高活性側 (5-6 と 6 以上) で稼いで、中間帯 (3-5) では返している。チャレンジの目的とは向きが合っているが、そこは隠さない

聞かれたら6 以上の -0.126 は一番大きい改善だが n=31 しかない
